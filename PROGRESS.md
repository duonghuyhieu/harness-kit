## Known Issues
- Claude Code ignores `permissions.allow` from a project's `<project>/.claude/settings.json` until the workspace is trusted
  (interactive trust dialog); hooks and deny rules still apply.
- The status line command uses a relative path (no project-dir variable for status lines): started from a
  subdirectory it shows an error instead of the harness line.
- Hooks fail open by design; secret protection relies on `permissions.deny`, and filesystem/network isolation on
  Claude Code's own sandboxing (documented in README and HUONG-DAN).
- Skills are exercised by frontmatter tests and manual runs only, not by automated agent runs.
- v1 known issues still apply (detectors not field-tested on non-Python/Node repos; PHP/Composer 1 caveat; `loop` is
  not a sandbox).
- The shell guard is a guardrail, not a parser: writes through e.g. `python -c "json.dump(...)"` are not caught; the
  gates (`verify`, `loop` integrity checks) remain the real protection. Open review items: install/update re-add
  rules or hooks the user removed on purpose; `uninstall` leaves the `$schema` key; empty projects still get H006.
